1. PRODUCT MODEL

mikrokhoros is one installed product containing:

- a user-global world catalog;
- user-global agent identities, profiles, and assignments;
- user-global object packages;
- user-global Inventory folders and source objects;
- trusted user-global world-template definitions;
- exact-world journals containing concrete agents, objects, deployments, template
  applications, listeners, reports, restock rules, objectives, Library documents,
  events, and model histories; and
- user-global configuration and host adapter availability.

The current world is a default command target. It is not a workspace, tenant,
ownership boundary, or global filter.

The browser is a graphical projection of the existing human command and management
contracts. It uses typed application services and exact runtime identities. The
exhaustive human command catalog and presentation-neutral results remain the single
definition shared with the CLI.


2. APPLICATION SHELL

The desktop browser application has two persistent regions:

1. a narrow left sidebar; and
2. the active product view filling the remaining viewport.

The sidebar has three independently laid-out zones:

- fixed header: product name, sidebar toggle, and app-view dropdown;
- scrollable middle: content belonging to the active app view; and
- fixed footer: Settings.

The visible product name is always lowercase mikrokhoros.

The canonical 1536 by 1024 state uses an expanded 304px sidebar. It may narrow at
compact desktop widths or collapse to a rail. The active view uses the remaining
width. A warm translucent tint, a narrow edge fade, and restrained backdrop blur
separate the two regions.


2.1 APP-VIEW BUTTON AND DROPDOWN

The first control below the product name is one 32px-high transparent-glass button:

  [ selected app view  v ]

It is a custom button and one anchored dropdown menu. Its closed state contains only
the current view icon, current view label, and chevron. Opening it reveals these
32px-high rows:

1. World
2. Agent Manager
3. Inventory
4. Packages
5. Templates

The current row has a checkmark and a restrained selected tint. The menu has 6px
outer padding and one warm-white translucent surface. Selecting a row closes the
menu and returns focus to the button.

Settings remains the fixed footer control.


2.2 CONTEXT CONTROL SLOT

The row immediately below the app-view button belongs to the selected view.

World
  Shows the world picker.

Agent Manager
  Begins the user-global agent list.

Inventory
  Begins the user-global Inventory folder and source tree.

Packages
  Begins the user-global package list and filters.

Templates
  Begins the trusted template catalog.

Settings
  Opens from the fixed footer and has its own settings navigation.

Only World owns a persistent world picker.

Action forms choose an exact target world when the action requires one. That choice
is scoped to the submitted action and has the same meaning as a temporary --world
selection. It does not change the saved current-world pointer.


3. VIEW AND SCOPE MAP


3.1 WORLD

Scope
  One exact route-selected world plus the user-global world catalog.

Sidebar header
  App-view button: World.
  World picker directly below it.

World-picker behavior
  The closed button shows the viewed world name, a globe icon, and a chevron.
  The menu lists managed worlds by display name and exact ID.
  A checkmark identifies the world displayed by this browser view.
  A compact Current label identifies the saved current-world pointer.
  Choosing a world changes the viewed route only.
  Make current invokes world use explicitly.
  Create, Import, Rename, Delete, Inspect, and Export are contextual commands in
  meaningful menu groups.
  World creation and import follow their implemented selection semantics.
  Destructive world deletion identifies the complete world ID and uses the
  canonical confirmation.

Scrollable sidebar middle

Agents
  Show the focused agent first and the nearest active agents in the displayed
  container until three rows are visible.
  Distance is Manhattan distance from the focus position.
  Equal distances sort by complete agent ID.
  A typed application service supplies the ordered projection to the browser.
  Other agents opens one custom dropdown containing the remaining registered agents.
  Clicking an agent focuses it and makes the world follow that agent.
  Manual panning suspends following until the human focuses an agent again.

Objects
  Inventory is the first 32px row and navigates to the global Inventory view.
  Exact world-level pinned objects follow it directly in the same Objects section.
  A pin stores only the complete world-object ID under the exact world ID.
  Clicking a pin focuses the same object and opens the same generic interface as
  direct selection in the world.

World header
  Left: the complete structural path of the currently shown container or focused
  entity, using the CLI grammar and system monospace.
  Right: Notifications immediately followed by View.
  Header controls remain 32px high and the header stays tight to the top edge.

Structural path
  Example:
  (0,0)@world/(0,1)["Workshop"#7a2f4d8c1b6e4a0f9c3d2e5b8a7f1c04]

  Complete 32-character lowercase IDs remain visible and selectable.
  Long paths reveal horizontally without inventing a browser-only breadcrumb.

Notifications
  The closed 32px control shows a bell, an unread indicator with accessible text,
  and one line from the latest stored human object report in this world.
  Overflow ends with an ellipsis.
  Opening it reveals one anchored report popover scoped to the viewed world.
  Rows retain exact report, object, Inventory, package, deployment, and world
  lineage.
  Selecting a report opens its generic human-management detail.

View
  One 32px transparent-glass button and one anchored custom dropdown.
  The menu contains zoom, recenter, visibility, display, and context-valid
  inspection actions.
  Choosing an action runs it, closes the menu, and restores focus to View.

World field
  The world has no visible grid, tiles, cell borders, axes, or checkerboard.
  Empty visible positions are quiet 3px dots.
  Objects and agents replace the dot with their deterministic SVG symbol.
  Agent identity, held-object, standing-object, and selection states use the
  canonical symbol grammar from docs/ui-design-draft.txt.

Cell hover
  Hover or keyboard focus opens one small overlay above and to the right of the
  pointer or focus target.
  The overlay contains local grid coordinates and one short information line.
  It uses 8px padding, system monospace for coordinates, system sans for the
  description, and a warm-white translucent surface.

Object selection
  Selecting an exact object opens the generic object human interface.
  The world remains visible and visually recedes behind the interface.

World capability coverage
  World catalog operations; exact world show/inspect/export; concrete object
  list/show/interface/action/view/move; exact-world objectives and Library
  operations; concrete listeners, reports, copies, restock state, and template
  application state are reached from the world, an exact object, or a corresponding
  contextual action.


3.2 AGENT MANAGER

Scope
  The complete user-global agent identity catalog.

Sidebar
  App-view button: Agent Manager.
  The next row begins the agent list.
  Each row shows identity, name, assignment state, and active/inactive presence.
  Filters may describe assignment or activity; they do not rescope the product.

Agent detail
  Complete agent ID.
  Name and creation metadata.
  Maximum actions per response.
  Initial/current coin presentation.
  Attached AI profile and adapter metadata.
  Exact assigned-world link when assigned.
  Active-world presence, structural path, hand, backpack, and genesis equipment
  when concrete state exists.
  Unread or retryable notification state.

Actions
  Create identity.
  Configure maximum actions.
  Add an unassigned agent to a chosen world and coordinate.
  Remove an active agent from its assigned world surface.
  Set, replace, or clear its AI profile.
  Retry the latest eligible unread notification.
  Submit a Messenger request with body, sender, thread, and priority.
  Submit the built-in orientation request.
  Grant finite or infinite coin.
  Open the bounded in-world action controller for the assigned agent.

The Add to world form contains an explicit World field. An assigned agent shows its
fixed exact-world link; its commands follow that assignment and cannot be redirected
by a free world switcher.

Equipment is an exact read-only view of agent lifecycle state. It is not an equipment
editor.

Provider attachment can trigger immediate work when unread input exists. The UI
shows committed profile state separately from the resulting provider task and world
action results.


3.3 INVENTORY

Scope
  User-global folders, source objects, source revisions, typed configuration,
  credential handles, capability grants, package lineage, and management state.

Sidebar
  App-view button: Inventory.
  The next row begins the permanent folder/source tree.
  Folder expansion, source selection, and filters operate on the global catalog.
  World-bound forks remain visible in this global tree and carry a Bound to world
  badge with their complete exact-world identity available in detail.

Source detail
  Exact Inventory ID and revision.
  Package ID, version, and content hash.
  Folder and fork provenance.
  Optional exact-world binding.
  Readiness, missing fields, missing credential handles, and missing grants.
  Redacted configuration.
  Requested and granted capabilities.
  Runtime-owned base management interface.
  Package-declared fields, actions, views, and report definitions.

Inventory actions
  Create, list, show, move, and logically delete a source.
  Create, list, show, rename, move, and delete folders.
  Configure typed non-secret fields.
  Set and clear write-only secret references.
  List, grant, and revoke capabilities.
  Run declared Inventory-scoped actions.
  Render declared Inventory-scoped views.
  Fork a source for one explicitly selected world.
  Deploy a ready source to one explicitly selected world and destination.

Exact-world subsections
  Copies, listeners, reports, and restock rules are shown inside a clearly labelled
  World activity section for one locally chosen exact world.
  Every value in this section is labelled with and computed from that chosen exact
  world.
  Its world choice is local to the subsection or action.
  A world-bound fork locks this choice to its bound world.

Copy deletion preserves dry-run, recursive containment preview, exact affected IDs,
canonical confirmation, and revalidation at commit.

Report rows and results remain bounded untrusted structured data and render as text
and typed values, never executable markup.


3.4 PACKAGES

Scope
  The user-global package catalog and retained package artifacts.

Sidebar
  App-view button: Packages.
  The next row begins Available and Installed package lists.

Package detail
  Package ID and semantic version.

Check status in world opens a compact target form with one required World field and

that world.

Apply to world opens a compact target form containing:

- World;

4. GENERIC OBJECT HUMAN INTERFACE

Every package and concrete object uses one host-owned interface shell. The selected
entity supplies structured management metadata and values.

The shell contains:

- deterministic SVG identity symbol;
- display name;
- exact object type;
- complete Inventory or concrete world-object ID;
- scope and revision;
- package/source/deployment lineage;
- host-owned base details;
- generated fields;
- declared management actions;
- declared management views; and
- declared report definitions and report results.

Navigation is generated from available content:

- Overview is always present.
- Configuration appears when applicable fields exist.
- Credentials appears when secret fields exist and exposes presence/usability only.
- Capabilities appears when the package requests capabilities.
- Each declared view is rendered from its ID, summary, scope, and typed result.
- Each declared action is rendered from its ID, summary, scope, typed inputs,
  mutating flag, required capabilities, and typed result.
- Copies, listening, reports, deployment, and restock appear only when the
  runtime-owned base interface makes them applicable.

Inventory scope changes one source revision.
World scope changes one exact concrete instance revision.
Both scopes render the action only in the selected interface where it is valid.

Supported management field controls:

  text       bounded text field
  integer    bounded integer field
  decimal    bounded decimal field
  boolean    switch
  choice     custom dropdown
  url        validated URL field
  path       human-only path field
  secret     write-only secure field

Package content supplies bounded structured management data. The host supplies all
controls, layout, icons, encoding, focus behavior, validation presentation,
confirmation behavior, and exact service calls.

The interface is a centered substantial surface with 32px outer corner radius. It
uses spacing, alignment, tint, and blur rather than a straight internal divider.
All interface buttons and selectable navigation rows are 32px high.

7. WEB HOST AND PLATFORM CONTRACT

khoros web starts the local browser host.

The browser transport is a thin adapter around typed application services. Domain
behavior stays independent of HTTP routing and frontend presentation.

The host transport stays dependency-free and keeps a small platform-neutral Swift
boundary. Native Windows, macOS, and Linux behavior is verified without binding
product semantics to a server framework. Any future transport dependency requires
license review, a concrete product need, Swift-version compatibility, and passing
macOS/Linux/Windows CI before adoption.

Host requirements:

- bind loopback interfaces only by default;
- validate Host and Origin;
- use an explicit local-session authentication decision;
- protect every mutation against CSRF;
- serve versioned local static assets with restrictive content security policy;
- encode all untrusted content as data;
- keep credentials write-only and out of browser persistence;
- resolve selectors to complete runtime IDs before authorization or mutation;
- use the existing product lock and recoverable transactions;
- stream report-follow data from the host without browser filesystem polling; and
- preserve the same cancellation, validation, confirmation, error, and mutation
  boundaries as the CLI.

The Windows build is a native Swift executable and uses no Unix shell or Darwin-only
runtime path.

9. ACCEPTANCE CRITERIA

- App-view selection is one button and one dropdown.
- World selection appears as persistent chrome only in World.
- User-global catalogs remain complete and unfiltered by a hidden world context.
- Exact-world action forms make their target world explicit.
- Templates renders trusted definitions and chooses a world inside status/apply.
- Agents follows exact assignment semantics.
- Inventory separates global source state from labelled one-world activity.
- Every object-specific form, action, and view comes from the typed management
  contract plus the runtime-owned base interface.
- Every routine control is 32px high.
- Capsules use the 48px radius token.
- Major overlays use a 32px radius.
- Typography, palette, transparent-glass rims, blur separation, gridless world,
  deterministic SVG identity, and system-monospace raw data match the canonical
  visual contract.
- Notifications precedes View and provides a one-line ellipsized report preview.
- Complete paths and IDs remain selectable and authoritative.
- Every implemented human command has one browser placement.
- khoros web remains native on macOS, Linux, and Windows.
- Browser actions preserve existing security, locking, transaction, confirmation,
  capability, credential, and error semantics.
