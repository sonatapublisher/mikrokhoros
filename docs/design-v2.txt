MikroKhoros Web design v2

Status: canonical browser-interface brief
Command: khoros web
Platforms: macOS, Linux, and native Windows
Runtime authority: ../README.md, design.md, security.md, and the exhaustive
human command catalog
Visual authority: ui-design-draft.txt plus the values fixed in this document


1. PRODUCT MODEL

mikrokhoros is one installed product containing:

- a user-global world catalog;
- user-global agent identities, profiles, and assignments;
- user-global object packages;
- user-global Inventory folders and source objects;
- trusted user-global world-template definitions;
- exact-world journals containing concrete agents, objects, deployments, template
  applications, listeners, reports, restock rules, objectives, Library documents,
  events, and model histories; and
- user-global configuration and host adapter availability.

The current world is a default command target. It is not a workspace, tenant,
ownership boundary, or global filter.

The browser is a graphical projection of the existing human command and management
contracts. It uses typed services and exact runtime identities. The
exhaustive human command catalog and presentation-neutral results remain the single
definition shared with the CLI.


1.1 DELIVERY BOUNDARY

The native `khoros` executable serves MikroKhoros Web from typed domain projections and
contextual actions. Each view presents the data, relationships, and tasks of one
product domain.

View             Scope and primary material
---------------  ---------------------------------------------------------------
World            Exact-world spatial projection, reports, object inspection, and
                 bounded exact-world command dock
Agent Manager    User-global agent identities, profiles, assignments, and presence
Inventory        User-global folders and source objects with local exact-world
                 activity sections
Packages         User-global available, installed, and retained package catalog
Templates        Trusted user-global template definitions and exact-world status or
                 web controls
Settings         Product configuration, diagnostics, adapters, limits, and terminal
                 preferences
Help             Searchable full command reference and contextual guidance

The host exposes bounded typed read projections at:

  GET /api/v1/agents
  GET /api/v1/inventory
  GET /api/v1/packages
  GET /api/v1/templates
  GET /api/v1/settings

These routes project data required by their corresponding domain view. They are not
command results and do not expose persistence files, credentials, private histories,
administrative snapshots, or executable behavior. Mutations continue through the
contextual action gateway described below.


2. APPLICATION SHELL

The desktop browser interface has two persistent regions:

1. a narrow left sidebar; and
2. the active product view filling the remaining viewport.

The sidebar has three independently laid-out zones:

- fixed header: product name, sidebar toggle, and app-view dropdown;
- scrollable middle: content belonging to the active app view; and
- fixed footer: Settings.

The visible product name is always lowercase mikrokhoros.

The canonical 1536 by 1024 state uses an expanded 240px sidebar. It may narrow at
compact desktop widths or collapse to a rail. The active view uses the remaining
width. A warm translucent tint, a narrow edge fade, and restrained backdrop blur
separate the two regions.


2.1 APP-VIEW BUTTON AND DROPDOWN

The first control below the product name is one 32px-high transparent-glass button:

  [ selected app view  v ]

It is a custom button and one anchored dropdown menu. Its closed state contains only
the current view icon, current view label, and chevron. Opening it reveals these
32px-high rows:

1. World
2. Agent Manager
3. Inventory
4. Packages
5. Templates

The current row has a checkmark and a restrained selected tint. The menu has 6px
outer padding and one warm-white translucent surface. Selecting a row closes the
menu and returns focus to the button.

All five rows are enabled. Selecting one closes the menu, updates the route, and
returns focus to the app-view button.

Settings remains the fixed footer control.


2.2 CONTEXT CONTROL SLOT

The row immediately below the app-view button belongs to the selected view.

World
  Shows the world picker.

Agent Manager
  Begins the user-global agent list.

Inventory
  Begins the user-global Inventory folder and source tree.

Packages
  Begins the user-global package list and filters.

Templates
  Begins the trusted template catalog.

Settings
  Opens from the fixed footer and has its own settings navigation.

Only World owns a persistent world picker.

Action forms choose an exact target world when the action requires one. That choice
is scoped to the submitted action and has the same meaning as a temporary --world
selection. It does not change the saved current-world pointer.


2.3 CONTEXTUAL ACTION LAYER

The exhaustive command catalog remains the shared CLI execution contract and the
searchable Help reference. It is internal web infrastructure: descriptors
bind named controls to field validation, completion, confirmation, private reveal,
download, report following, and refresh behavior. Descriptors never supply the
MikroKhoros Web’s primary navigation, sidebars, default selection, or page structure.

Every action begins from the selected domain entity or a deliberately placed
contextual control. A compact action sheet contains only the fields, consequence
review, result, or stream required for that action. Fixed choices and exact-world
selection use custom dropdowns; identity fields use bounded editable completion.
Credential entry is write-only. Consequential changes prepare a session-bound plan
before explicit Confirm or Cancel.

Help is the one full searchable command-reference surface. It explains a command’s
scope, arguments, and safe route to its contextual control without replacing the
current domain view. The World map stays spatial while contextual world controls and
the exact-object interface remain available in place.


3. VIEW AND SCOPE MAP


3.1 WORLD

Scope
  One exact route-selected world plus the user-global world catalog.

Sidebar header
  App-view button: World.
  World picker directly below it.

World-picker behavior
  The closed button shows the viewed world name, a globe icon, and a chevron.
  The menu lists managed worlds by display name and exact ID.
  The final row is always Create new world, including when the catalog is empty or
  the selected projection cannot open.
  A checkmark identifies the world displayed by this browser view.
  A compact Current label identifies the saved current-world pointer.
  Choosing a world changes the viewed route only.
  Viewing a world restores that exact world's bounded browser-local My-view state as
  a route/camera hint, then reloads the ordinary authoritative projection.
  Make current invokes world use explicitly.
  Create new world opens a compact custom form with one bounded name field. The
  committed bare world becomes current and opens through its exact returned route.
  Rename, Delete, Inspect, and Export are available through contextual World
  controls and searchable Help.
  Destructive world deletion identifies the complete world ID and uses the
  canonical confirmation.

Scrollable sidebar middle

Agents
  Keep one persistent My view row separate from the exact world's active-agent
  roster. The collapsed roster shows the first three agents in stable per-world
  order.
  My view is a flat, single-line row containing only its icon and visible label;
  camera, path, coordinate, and zoom remain accessibility metadata.
  The first exact-world projection seeds a stable agent order. Explicit agent
  selection promotes that agent; follow refresh and My view restoration preserve
  the surviving order. Newly visible agents append and unavailable agents disappear.
  Explicit selection is the sole focus-changing interaction.
  A compact `All X agents` disclosure appears after the collapsed rows, where X is
  the exact active count. It contains no separate trailing count badge and is absent
  when fewer than three agents are active. Expanding it replaces the collapsed roster
  with every active registered agent in the same row treatment and stable per-world
  order.
  Selecting an agent from the expanded roster focuses it and starts scoped live follow,
  refreshing through the ordinary World projection approximately every 1.8 seconds.
  Collapsing is triggered by the same `All X agents` control and returns to the three-row
  collapsed state.
  Adding an agent is a separate world-agents mutation: it requires an existing
  user-owned identity selector, integer `x` and `y`, and an explicit `auto-adapt`
  choice, reloads the authoritative world, and preserves the prior focus/follow state.
  Manual panning, zooming, container click, or a view-target action cancels follow
  immediately and does not re-enable it until a new explicit focus selection.
  Agent focus and follow preserve the saved My-view container, camera, and zoom.
  Selecting My view restores that state while preserving roster order.

Objects
  Inventory is the first 32px row and navigates to the global Inventory view.
  Exact world-level pinned objects continue immediately after it as one uninterrupted
  Objects list.
  A pin stores only the complete world-object ID under the exact world ID.
  Clicking a pin focuses the same object and opens the same generic interface as
  direct selection in the world.

World header
  Left: the complete structural path of the currently shown container or focused
  entity, using the CLI grammar and system monospace.
  Right: Notifications immediately followed by View.
  Header controls remain 32px high and the header stays tight to the top edge.

Structural path
  Example:
  (0,0)@world/(0,1)["Workshop"#7a2f4d8c1b6e4a0f9c3d2e5b8a7f1c04]

  Complete 32-character lowercase IDs remain visible and selectable.
  Long paths reveal horizontally without inventing a browser-only breadcrumb.

Notifications
  The closed 32px control shows a bell, an unread indicator with accessible text,
  and one line from the latest stored human object report in this world.
  Overflow ends with an ellipsis.
  Opening it reveals one anchored report popover scoped to the viewed world.
  Rows retain exact report, object, Inventory, package, deployment, and world
  lineage.
  The browser stores one exact-world latest-seen report marker and derives the unread
  dot as a boolean. It computes N from the returned bounded recent-report list; the
  DTO does not claim an unread count, complete history, or a global total.
  Selecting a report opens its generic human-management detail.

View
  One 32px transparent-glass button and one anchored custom dropdown.
  The closed button contains the View label and chevron.
  The menu contains zoom, recenter, visibility, display, and context-valid
  inspection actions.
  Choosing an action runs it, closes the menu, and restores focus to View.

World field
  The world has no visible grid, tiles, cell borders, axes, or checkerboard.
  Empty visible positions are quiet 3px dots.
  A placed object replaces the dot with its deterministic SVG body. Agent occupancy
  is represented entirely through the canonical cell outline, fill, and held-object
  state.
  Every position uses a 48px base equal-width, equal-height rounded-square target.
  Adjacent cells touch without spacing. Zoom scales the complete target, dot,
  identity shape, outline, count, and label together.
  Empty and ordinary nonholding targets stay transparent. Hover, keyboard focus, and
  a stationary press or hold share one brightness-only feedback treatment.
  A placed object remains independently reachable through the cell occupant model
  when a colocated agent's held-object silhouette owns the visible body.
  Agent identity, held-object, standing-object, and selection states use the
  canonical centered, geometrically balanced symbol grammar from
  docs/ui-design-draft.txt. Each silhouette has its own visually balanced 24px
  keyline. Filled area is retained as a quantitative reference, while apparent
  extent, density, negative space, and recognition determine final size. Every true
  filled-area centroid is normalized to (128,128).

Cell click and drag arbitration
  A single click on any world cell opens one anchored custom cell dropdown. Empty
  cells expose their coordinate and Empty position; occupied cells expose their
  occupants and context-valid actions. For a generic container, defer that menu by
  200ms so a valid double-click on the same object can cancel it and navigate
  directly into the container.
  When an object-bearing cell dropdown is open, the next primary click on an empty
  World cell closes that dropdown and is consumed. A later activation opens the
  empty-cell dropdown normally. Crossing the drag threshold still proceeds into
  ordinary World panning.
  Drag capture for world interaction begins only after pointer travel crosses 6px.

Cell detail
  Hover or keyboard-cell focus updates the Agent/Object information panel only.
  Agent and Object each expose `Press C to keep detail`; `C` keeps the current or
  most recently pointed-to coordinate after pointer exit and changes the control to
  `Press C to follow hover`. Pressing it again resumes live pointer/keyboard context.
  Kept context is page-memory state and clears on exact World or container change.
  Click, Enter, or Space opens the anchored custom cell dropdown for both empty and
  occupied cells.

Object selection
  Selecting an exact object opens the generic object human interface.
  The open inspector tab is remembered per exact object per exact world and restored
  when returning to that same object view.
  The world remains visible and visually recedes behind the interface.

World action placement
  World catalog controls, exact-world inspection/export, selected concrete-object
  actions, notifications, and template status/application are available only from
  their relevant World or object context. The map remains the World work region.
  Help documents the full command set, while the immediate dock is limited to the
  exact-world allowlist below.

World command console
  A floating dock sits at the bottom of the World field. The monospace command input
  is a separate 40px-high capsule from the command-information panel above it. The
  panel is resizable from a centered pill handle on its top edge and minimizable.
  Its selected body scrolls internally. Its horizontal tabs are Output, Agent, and
  Object, with short vertical separators between them. Visible `1`, `2`, and `3`
  hints switch those tabs outside editable fields and modal/menu surfaces, expanding
  the information panel without moving focus.
  Output holds the bounded command transcript. Agent and Object show the context
  selected by hovering a World cell, and that context appears exclusively in the
  panel while the World field keeps quiet target feedback. Context is exact-world
  scoped and clears when the selected World or shown container changes. Their `C`
  control keeps or releases the selected coordinate independently of pointer exit.
  Cell menus and object interfaces require activation.
  Autocomplete is capped at eight suggestions from the canonical catalog and its
  bounded completion providers. Syntax styling is bounded inert text rendering.
  Entries are FIFO and nonretrying, with one command in flight. The transcript is
  memory-only, bounded, and inert; it is not browser persistence or CLI history.
  The host uses the same catalog, tokenizer, parser, and executor as the CLI and
  never invokes an operating-system shell or subprocess.

  The exhaustive deny-by-default immediate-console allowlist is:

    help
    world show
    world template status
    world object list
    world object interface
    world object action list
    world object view list
    world object move

  Every request carries the exact World route selection. The host validates that
  world ID against the catalog and file, injects its global context, and rejects a
  `world show` selector that resolves elsewhere. A successful `world object move`
  reloads the authoritative projection for that exact World.

4. GENERIC OBJECT HUMAN INTERFACE

Every selected Inventory source and selected concrete world object uses one host-
owned interface shell. The selected entity supplies structured management metadata
and values.

The shell contains:

- deterministic SVG identity symbol;
- display name;
- exact object type;
- complete Inventory or concrete world-object ID;
- scope and revision;
- package/source/deployment lineage;
- host-owned base details;
- generated fields;
- declared management actions;
- declared management views; and
- declared report definitions and report results.

Navigation is generated from available content:

- Overview is always present.
- Configuration appears when applicable fields exist.
- Credentials appears when secret fields exist and exposes presence/usability only.
- Capabilities appears when the package requests capabilities.
- Each declared view is rendered from its ID, summary, scope, and typed result.
- Each declared action is rendered from its ID, summary, scope, typed inputs,
  mutating flag, required capabilities, and typed result.
- Copies, listening, reports, deployment, and restock appear only when the
  runtime-owned base interface makes them applicable.

Inventory scope changes one source revision.
World scope changes one exact concrete instance revision.
Both scopes render the action only in the selected interface where it is valid.

Supported management field controls:

  text       bounded text field
  integer    bounded integer field
  decimal    bounded decimal field
  boolean    switch
  choice     custom dropdown
  url        validated URL field
  path       CLI-only declared field; the browser displays its contract but accepts no value
  secret     write-only secure field

A contract containing any declared `path` field or `path` action input remains
visible as contract metadata, but all of its actions and views are labelled CLI
only. A view sourced from configuration is also CLI only. The browser never offers
set or unset controls for the path field itself.

Package content supplies bounded structured management data. The host supplies all
controls, layout, icons, encoding, focus behavior, validation presentation,
confirmation behavior, and exact service calls.

The interface is a centered substantial surface with 32px outer corner radius. It
uses spacing, alignment, tint, and blur rather than a straight internal divider.
All interface buttons and selectable navigation rows are 32px high.

Browser-local presentation preferences are limited to bounded exact-world pin IDs,
latest-seen report IDs, My-view state, and last inspector tabs. Every stored value is
validated when used and remains outside product authority and persistence.

5.3 GEOMETRY AND DENSITY

- Every routine button, dropdown trigger, selectable sidebar row, tab, and compact
  action is exactly 32px high.
- Every routine icon-only control is 32px by 32px.
- Every standalone action button, pressed toggle, modal or dialog control, icon
  control, and closed custom-dropdown or selector trigger is exactly 32px high and resolves the
  `--pill-radius` token as a complete smooth capsule. Transparent Project Genie construction remains
  limited to its designated chrome controls; other standalone capsules retain their
  own documented surface treatment.
- Repeated sidebar rows, menu items, report rows, tabs, and world cells use flat row
  or map treatments rather than the Genie surface.
- The domain search control is a complete 32px capsule. Ordinary editable inputs and
  content surfaces retain the local 12px treatment unless they are a closed selector
  trigger.
- Major overlays use a 32px radius.
- The World command-information panel uses a 24px radius.
- Menus and compact floating surfaces use a 16px radius.
- Every non-circular `border-radius` declaration resolves through
  `--smooth-corner: superellipse(1.78)`, including `--pill-radius` capsules and
  clipped transparent-glass layers. Numeric radius tokens remain authoritative.
  The three semantic circle/dot selectors explicitly resolve through `round`; the
  original Identity Shape SVGs and masks retain their authored geometry.
- Standard pane padding is 8px.
- Reading-heavy content may use 12px.
- The spacing scale is 4, 6, 8, 12, 16, and 24px.
- Interface icons are vendored Phosphor Bold at 14 to 16px. Identity silhouettes
  use the original project-owned MikroKhoros Identity Shapes set.
- Search fields use the plain Phosphor Magnifying Glass; the Plus and Minus variants
  are reserved for explicit World zoom controls.
- Controls grow horizontally for content and retain their 32px height.
- Clipped 32px glass controls use a 20px label line box so rounded Google Sans Flex
  descenders remain complete while one-line ellipsis behavior is preserved.
- Headers are content-tight with 6px vertical inset around 32px controls.
- Nested cards are replaced by alignment, spacing, and subtle tonal regions.

Shared web workspace frame
  All non-World web views share `--workspace-column-max: 1080px` and
  `--workspace-inline-gutter: clamp(18px, 2.4vw, 36px)`. Their header, transient
  transient state, and scrollable content resolve to the same left and right
  edges. Compact views use the identical frame rather than an independent inset or
  narrower column. Detail sections use a 16px section cadence, 8px between paired
  fields or controls, and 6px between a label and its immediate supporting content.

5.5 DROPDOWNS AND POPOVERS

- Custom rendered throughout.
- One 32px trigger opens one anchored surface.
- Surface-primary with 16px radius, a light-only perimeter, and 6px padding.
- Rows are flat and 32px high; they have no clipped blur or reflected capsule edge.
- Text-only choice rows use a flexible label track followed by optional trailing
  state, so labels remain complete without reserving a leading identity-icon column.
- Current selection uses a checkmark plus selected tint.
- Escape and outside click close the surface.
- Selection closes the surface and restores focus.
- Only one dropdown, report popover, or object inspection popover is open at a time.

7. WEB HOST AND PLATFORM CONTRACT

khoros web starts the local browser host.

The browser transport is a thin adapter around typed services. Domain
behavior stays independent of HTTP routing and frontend presentation.

The current host transport uses SwiftNIO 2.101.3 through a small platform-neutral
Swift adapter. Product semantics remain in presentation-neutral services.
Transport dependency changes require license review, a concrete product need,
Swift-version compatibility, and passing macOS/Linux/Windows CI before adoption.

Host requirements:

- bind loopback interfaces only by default;
- validate Host and Origin;
- use an explicit local-session authentication decision;
- protect every mutation against CSRF;
- serve versioned local static assets with restrictive content security policy;
- encode all untrusted content as data;
- keep credentials write-only and out of browser persistence;
- resolve selectors to complete runtime IDs before authorization or mutation;
- use the existing product lock and recoverable transactions;
- stream report-follow data from the host without browser filesystem polling; and
- preserve the same cancellation, validation, confirmation, error, and mutation
  boundaries as the CLI.

The Windows build is a native Swift executable and uses no Unix shell or Darwin-only
runtime path.

The immediate World command routes are POST-only, same-origin,
session-authenticated, and query-free. Each accepts only `{worldID, source}` with
strict primitive JSON, exact content type, duplicate-key rejection, an 8 KiB request
bound, and a 4,096-character source bound. Each captured output channel is capped at
65,536 bytes and completion at eight suggestions.

The web capability transport exposes authenticated catalog, completion,
finite execution, prepare/commit, secret, agent-controller, and report-follow
routes. Bodies are capped at 64 KiB, reject duplicate keys recursively, and accept
only one operation ID, declared string-array fields, an optional exact world ID, and
the endpoint's typed private value. The host injects layout, configuration, output,
color, session, and exact-world globals. Stdout and stderr share one aggregate
256 KiB finite-output budget. Confirmation plans are session-bound,
persistent-state-bound, count-bounded, expire after 90 seconds, and are single-use.
Credentials use forced write-only standard input with a 16 KiB gateway ceiling.
Report follow is a cancellable session-expiring chunked exact-world stream with an
eight-stream cap, newest-snapshot buffering, and awaited transport writes. Accepted
private exports become attachments only when the complete output fits the aggregate
finite budget; command failure or truncation stays an ordinary rejected JSON result.
A busy execution returns `409`; the browser never retries. Successful mutations
refresh the descriptor's authoritative targets.

The five authenticated web projection routes are read-only and serve bounded
typed domain data for Agent Manager, Inventory, Packages, Templates, and Settings.
They recover pending product transactions and acquire the canonical product lock
before projecting their domain. They do not accept browser-supplied product paths,
configuration, session globals, or world authority. Settings may expose typed
non-secret runtime configuration values; Inventory exposes configuration and
credential field presence only. The response schema excludes credential values and
handles, local executable paths, raw persistence documents, private histories,
administrative snapshots, and capability closures. A view refresh always reloads its
authoritative projection rather than parsing a prior action result as domain state.

9. ACCEPTANCE CRITERIA

- App-view selection is one button and one dropdown.
- World selection appears as persistent chrome only in World.
- User-global catalogs remain complete and unfiltered by a hidden world context.
- Exact-world action forms make their target world explicit.
- Templates renders trusted definitions and chooses a world inside status/apply.
- Agents follows exact assignment semantics.
- Inventory separates global source state from labelled one-world activity.
- Every object-specific form, action, and view comes from the typed management
  contract plus the runtime-owned base interface.
- Every routine interactive target retains the 32px height.
- Only designated standalone controls use the `--pill-radius` Project Genie capsule; repeated
  navigation, menu, report, and tab rows remain flat.
- Major overlays use a 32px radius.
- Header, transient state, and content in every non-World web view share
  the 1080px responsive workspace frame, with the 16/8/6 detail rhythm and no
  view-local horizontal offset.
- Every non-circular rounded surface, including `--pill-radius` capsules and
  transparent-glass layers, uses `--smooth-corner: superellipse(1.78)`. The three
  semantic circle/dot selectors use `round`; Identity Shape SVGs and
  masks retain their authored geometry.
- Typography, palette, transparent-glass rims, blur separation, gridless world,
  deterministic SVG identity, and system-monospace raw data match the canonical
  visual contract.
- Notifications precedes View and provides a one-line ellipsized report preview.
- The collapsed roster shows the first three active agents in stable per-world
  order. At three or more agents, `All X agents` expands the complete roster inline
  and carries no trailing count badge.
- Agent follow is explicit and scoped; while selected, it refreshes approximately
  every 1.8s without overlap, and any manual camera action exits follow immediately.
- World-cell interactions use 200ms click/double-click arbitration and a 6px drag
  capture threshold.
- Empty and occupied world cells open the custom cell dropdown on click or keyboard
  activation. Hover and keyboard-cell focus update only the Agent/Object information
  panel and never open a menu or inspector. `C` keeps/releases that context, while
  `1`, `2`, and `3` switch Output, Agent, and Object outside editable/modal surfaces.
- Notifications and reports are exact-world bounded; the browser maintains a
  latest-seen marker and computes N from the returned recent slice.
- Complete paths and IDs remain selectable and authoritative.
- Help is the searchable reference for every current human command leaf. Named
  contextual controls bind relevant commands to the selected domain entity without
  turning the command catalog into browser navigation.
- khoros web remains native on macOS, Linux, and Windows.
- Browser actions preserve existing security, locking, transaction, confirmation,
  capability, credential, and error semantics.
