# Governance

MikroKhoros currently uses a maintainer-led model appropriate for an early project.
Maintainers set release scope, review contributions, preserve the product and
security invariants in `docs/design.md`, and make final merge decisions.

Technical decisions should be made in public issues or pull requests when they do
not involve an undisclosed vulnerability. Decisions favor demonstrated agent UX,
small complete primitives, deterministic enforcement, portability, and evidence from
tests over speculative infrastructure.

Contributors earn greater responsibility through sustained, constructive work and
sound review judgment. If the maintainer group grows, this document should be updated
with explicit roles, nomination/removal procedures, voting rules, and a conflict
resolution process. Until then, no unstated title or contribution count grants merge,
release, moderation, or security-disclosure authority.
